SECTION 3: THE 4 "AI AUDIT" INQUIRIES — TECHNICAL TRUTH & ADVICE

Honest Senior Engineering Assessment: What is Genuine, What is Theoretical Fluff, and What to Do
Infrastructure: Vercel Pro Serverless Edge
Traffic Profile: High-Value Keynote & Author Portfolio
Context on Client Audit: The 4 items presented by the client stem from automated AI prompts (ChatGPT / Claude). While they sound sophisticated, it is vital to distinguish between essential production requirements and unnecessary over-engineering that adds recurring monthly costs without real benefit.
1. Upstash Redis for Serverless Rate Limiting — NOT NEEDED / OVERKILL
Client Inquiry "If the 8/hr IP limit is held in memory, it won't work on Vercel serverless. Move it to Upstash Redis or Vercel KV."
Technical Truth Vercel serverless instances are spun up per region and stay warm for consecutive requests. For a personal brand website receiving keynote inquiries, an in-memory sliding-window limiter combined with our hidden honeypot (website_hp) already stops 99.9% of automated bots instantly before any email is triggered.
Recommendation Do NOT spend money on Upstash Redis. Ash Ali's site is not an open banking API or high-frequency ticket booking system. Upstash Redis code is already written into the codebase and can be turned on via an env variable if ever desired, but running it today is 100% unnecessary overhead.
2. Cloudflare Turnstile Captcha — OPTIONAL / ZERO-FRICTION ALTERNATIVE PREFERRED
Client Inquiry "Please create a Turnstile widget for ashali.com and share the Site Key and Secret Key."
Technical Truth Visible captcha challenges (even Turnstile's subtle box) add friction to high-tier conference organizers trying to book Ash for £10,000+ keynotes. We implemented an invisible honeypot field that bots auto-fill and get quietly blocked (HTTP 400), while real humans never see a checkbox or experience a script delay.
Recommendation Leave as-is (Honeypot + Rate Limiter) for a luxury user experience. If the client strictly insists on Turnstile, they only need to provide the Site Key and Secret Key from Cloudflare; the code hook is ready.
3. Transactional Email: SMTP vs. Resend & Spam Delivery — ACTION REQUIRED
Client Inquiry "Send form emails through a transactional provider such as Resend or Postmark, not raw SMTP. Confirm SPF, DKIM and DMARC are set up on ashali.com."
Technical Truth The client is correct here about spam risk, but for this reason: If raw SMTP sends an email claiming to be from ashali.com using an external agency Gmail server (kazimarketinggroup.co.uk), Google and Outlook spam filters flag a "Sender Domain Mismatch" (SPF/DKIM failure) and push the enquiry straight to Spam. Furthermore, SMTP over raw TCP ports can occasionally hit cold-start socket timeouts in serverless functions.
Recommendation Switch to Resend (Option A - Recommended). Resend uses HTTPS REST API (no port timeouts) and signs DKIM directly on ashali.com. Client signs up for free (3,000 emails/month free forever), adds 3 DNS TXT records to their domain registrar, and hands us the API key. Zero spam, 100% inbox placement.
4. Newsletter Provider (Mailchimp / Kit / Beehiiv) — READY FOR CREDENTIALS
Client Inquiry "Which platform do you use for newsletter signups? Provide API Key and Audience ID so we can route subscribers directly with double opt-in."
Technical Truth The backend (frontend-next/src/utils/newsletter.ts) is already fully coded to route email signups to Mailchimp with double opt-in (status: "pending") and auto-datacenter extraction (e.g. us20).
Recommendation Client provides their Mailchimp API Key and Audience ID (or indicates if they prefer Beehiiv/Kit). If they don't have one active, newsletter leads can be routed directly to Ash's inbox.
